## Context

动机和范围见 `proposal.md`。当前 `_TaskExecution.message` 初始为 `None`，`_execute_task` 在最终收尾时写入总结或失败、取消结果。`_update_progress` 只维护完成步骤数及已有页面 URL，未维护动作描述。

`ShadowAgent._on_step` 已接收模型输出的本步动作，并在节奏等待完成后调用 `register_new_step_callback`。现有实现限制每步一个动作，可直接复用这条回调链路。状态接口已经将取消和人工接管提示置于普通消息之上，并避免旧接管快照覆盖终态。

## Goals / Non-Goals

**Goals:**

- 在现有任务对象中维护一个轻量的动作描述，使宿主沿用现有轮询接口。
- 使用确定性的中文格式化规则，区分将执行的动作和已完成的最终结果。
- 通过隔离测试验证描述更新、终态保护和只读查询，不启动实际桌面任务或请求真实模型。

**Non-Goals:**

- 不新增动作历史、可靠消息投递、推送接口或新的响应字段。
- 不改变 OS 动作、权限、审计、模型提示词及每步动作数量。
- 不改变独立 TypeScript Agent 服务、Electron 装配、数据库或发布包。

## Decisions

### 复用本步模型输出回调

在 `api/server.py` 构造 Agent 时传入 `register_new_step_callback`，通过 `ShadowAgent._on_step` 已有转发更新对应任务记录。这一时点位于模型决策和节奏等待之后、动作执行之前，适合展示 `正在导航`、`正在点击` 等描述，不能写成动作已成功。

其他方案包括在 `OSController.act` 新增回调，或在 HTTP 查询时从历史推导消息。前者扩大控制器改动和回调生命周期管理范围；后者只能在动作完成后获得历史，且把查询与内部运行对象耦合。因此本次使用已有回调，不改写执行循环。

### 独立格式化动作描述

在 `api/progress.py` 提供纯格式化函数，接收本步模型输出，读取第一个非空动作，返回中文描述或 `None`。固定动作使用映射表，未知动作返回通用描述，无动作不清除已有消息。

导航独立提取模型输出的 `url`，直接拼接到 `正在导航 ` 后，不补协议、不去除首尾空白，也不解析或校验网址。本地服务地址及 `file://` 等字符串均原样展示；缺失、空字符串或非字符串时只显示 `正在导航`。展示层不决定实际导航是否允许，不改变执行器的原有校验。格式化模块不导入桌面、浏览器或模型运行模块，以保留 API 的延迟加载行为。

输入和按键描述不包含参数正文；`done` 只显示 `正在整理任务结果`。人工接管提示继续由现有接管快照决定，不能用动作参数替代真实接管状态。

### 保存消息与任务状态分离

动作回调只更新 `record.message`，不更改 `status`、`steps_completed` 或 `current_url`。任务必须仍为 `running`，且未受理取消、未进入 `finishing`，才能接受普通动作消息。回调仅做同步赋值，不引入新的异步等待或消息队列。

一次动作结束后，最新描述可保留至下一动作或状态变化。`get_status` 继续只读，仍由现有逻辑优先展示取消、人工接管和终态结果。任务最终消息仍由 `_execute_task` 的原有收尾逻辑统一写入。

### 兼容性与测试范围

`ProgressResponse.message` 保持 `str | None = None`，不添加字段描述或示例，响应字段和可空类型保持不变。为格式化函数添加参数化测试；通过现有 API 测试夹具触发构造参数中的步骤回调，在动作执行被阻塞时轮询，验证无需等到步骤结束即可展示消息。

增加接管、取消、收尾和终态的覆盖，确认旧回调不能覆盖最终结果。沿用现有只读查询和任务隔离断言，并补充导航目标与已到达页面 URL 不混淆的场景。测试不依赖真实浏览器、远程模型或数据库。

## Risks / Trade-offs

- 宿主轮询可能错过短暂动作 → 用户已选择只返回当前动作，规格明确不补发历史。
- 模型动作名称和参数形状异常 → 使用安全的通用描述或保留已有消息，不让格式化错误中断任务。
- 控制状态与动作回调先后交错 → 复用现有状态优先级，并在记录写入前检查取消、收尾及终态。
- 目标 URL 与当前页面混淆 → 导航目标仅用于消息；`current_url` 继续依据已有页面历史维护。

## Migration Plan

无需数据迁移或新增依赖。应用代码更新后重启 Shadow 服务即可使用；回退该改动会恢复运行期间通常没有动作描述的旧行为，宿主调用方式保持不变。
