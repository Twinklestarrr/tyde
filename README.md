# tyde

项目原名为 `tyde-outside`。为兼容已有环境，数据库名与角色名、已部署的 Vercel 域名及桌面应用标识 `app.tydeoutside.desktop` 保持原值。

React + Electron + Fastify + PostgreSQL 的 pnpm Monorepo。Web 与桌面共用 `apps/web`，使用 Tailwind CSS、shadcn/ui、TanStack Router 和 React Query。认证入口提供“验证码登录 / 密码登录”双页签，默认验证码登录；认证操作均访问当前后端，支持短信或密码登录、统一注册、会话恢复及退出。前端不生成或在本地校验验证码；当前短信仅 mock，发码成功后保留服务端提示，并展示与后端共用的固定测试码。后端已升级统一账号，所有账号自带领航员/策略官/执行专家，提供当前会话角色切换、登录后独立创建组织、本人全部组织摘要、刷新令牌、密码重置、用户资料更新、组织成员与审批、成员导入及文件上传台账；客户端已接入真实角色切换与组织创建，多组织选择尚未接入，真实短信尚未接入。后端字段和迁移说明见 [认证后端上下文](docs/AUTH_BACKEND.md)。

Agent W1 已提供两个应用骨架、pi-web 前端基础代码、21／22 号 v0.1 共享契约、事件解析及受控开发身份。W2 增加固定 Pi 1.3.0、内存多轮、流式、停止／故障处理与无界面验收入口。模型主入口通过服务端 URL 与 Key 配置，默认官方 DeepSeek；24 号平台转发保留为独立可选路径。W3 已接入私有会话、任务命令、快照历史、产品 SSE、页面多轮聊天与停止。用户已提供 W2 Flash 真实两轮召回、流式及停止通过的日志；W3 浏览器验收和内存限制见 [验证记录](docs/AGENT_W3_VALIDATION.md)。PostgreSQL、正式平台身份与 Electron 装配仍待后续工作包。分工和边界见 [Agent 开发与跨端协作](docs/AGENT_DEVELOPMENT.md)。

## 环境

- Node.js 24（基线 24.19.0），pnpm 11.23.0。使用 `nvm use` 切换 Node；不要自动升级 pnpm 主版本。
- 开发连接 `apps/server/.env` 指定的远程 PostgreSQL；需要本机数据库时可使用 Postgres.app PostgreSQL 18。不需要 Docker 或 Podman。
- 首次依赖安装需要 npm 网络；Electron 安装与打包还会下载二进制。
- Mac 包在 macOS 构建；Windows 包优先在 Windows x64 构建。用户安装客户端无需这些开发工具。

## Agent 独立开发

完成 `pnpm install` 后分别启动两个终端。启动页面无需业务数据库；真实聊天需要服务端模型 URL／Key 及显式开发身份配置，步骤见 [Agent 服务](apps/agent/README.md#w3-浏览器聊天与本机身份)：

```sh
pnpm dev:agent      # http://127.0.0.1:3002，Swagger /api/v1/docs/
pnpm dev:agent-web  # http://127.0.0.1:3003
```

页面通过自身客户端访问 Agent API 与产品 SSE，支持新建／切换会话、自由输入、连续追问、流式、停止、历史及同进程重连。开发身份凭据只放页面内存，刷新后重新输入；服务重启会清空会话。端口、环境变量与生产代理说明见 [Agent 服务](apps/agent/README.md) 和 [Agent 界面](apps/agent-web/README.md)，pi-web 固定版本及导入范围见 [上游记录](apps/agent-web/upstream/pi-web/SOURCE.md)。

`@tyde/shared/agent` 导出命令、查询与 SSE 的 DTO、Schema 和 `validateAgentContract`。本地源快照与生成规则见 [契约说明](packages/shared/src/agent/contracts/README.md)；`pnpm check:agent-contracts` 校验生成代码一致性，`pnpm test:agent` 另覆盖 Pi／MaaS 隔离回归。测试夹具不参与页面请求或生产响应。W4 新增独立工具过程与可靠事件，21 保持 `1.1.0-design`、22 为 `1.2.0-w4-design`，公开 schema_version 仍为 1，共 103 个 Schema；旧严格客户端需配套升级，未知事件仍失败关闭。

W4 通用宿主接口支持显式工具和可信 Skill 正文预加载、固定资源摘要、原生捕获及页面追溯。具体只读演示工具、合成数据和 Skill 仅在本机忽略目录，不随 main 交付；默认启动仍为普通聊天。独立环境与真实模型证据、W5 对接边界见 [W4 验收](docs/AGENT_W4_VALIDATION.md) 和 [逐文件交付清单](docs/AGENT_W4_DELIVERY.md)。

```sh
pnpm typecheck:agent
pnpm test:agent
pnpm build:agent
pnpm build:agent-web
```

W2 本地验收使用独立命令，无需先启动 HTTP 服务、页面或数据库。在 `apps/agent/.env` 填写模型 URL 和 Key；默认官方 DeepSeek 的 `deepseek-flash`：

```dotenv
AGENT_MODEL_BASE_URL=https://api.deepseek.com/v1
AGENT_MODEL_API_KEY=
```

把实际 Key 填在上述等号后，仅保存到忽略的 `.env`。其他 OpenAI 兼容地址另填 `AGENT_MODEL_ID`。在仓库根目录执行：

```sh
pnpm --filter @tyde/agent smoke:model --check-config
pnpm --filter @tyde/agent smoke:model
pnpm --filter @tyde/agent smoke:model --stop-after-ms 2000
```

配置检查不发送模型请求；默认冒烟验证两轮与上下文召回，停止时机可调整。完整配置见 [Agent 服务](apps/agent/README.md#url-与-key-本地验收)。原 `smoke:maas` 只用于可选的 24 号平台契约验收，独立要求平台身份／路由配置，两条路径不会自动回退。页面已使用同一服务端 URL／Key 模型入口。隔离测试与真实浏览器验收分开记录，内存模式不承诺重启恢复或持久提交。

业务开发、Vercel 与桌面构建入口继续按原流程运行；Agent 独立部署与双视图装配后续接入。

## 首次运行（Mac）

在项目根目录安装依赖：

```sh
pnpm install
```

在 Git 忽略的 `apps/server/.env` 中配置开发库 `DATABASE_URL` 及后端环境变量，本机或远程数据库均可，未配置时参考 `apps/server/.env.example`；已有配置无需覆盖。启动前确认目标库已应用现有迁移，数据库迁移由维护者单独执行。

如需本机数据库，先安装 [Postgres.app](https://postgresapp.com/)，再执行以下准备命令：

```sh
pnpm db:local:start
pnpm setup:local
pnpm db:deploy
```

`db:local:start` 自动查找已安装的 Postgres.app、Homebrew PostgreSQL 18 或 PATH 中的 PostgreSQL 工具，在本项目 `.local/postgres` 下创建独立数据库实例，仅监听回环地址 5432，数据不提交 Git。若 Postgres.app 或其他数据库已占用 5432，请选择一种实例运行方式，不要同时启动两个实例。

`setup:local` 创建 `tyde_outside_dev` 角色、开发库和专用自动化测试库，生成随机凭据到 `apps/server/.env` 与 `.env.test`（权限 0600）。它不会覆盖已有 `.env` 或重置已有角色密码。已有数据库时可自行复制 `.env.example` 并配置；特殊 PostgreSQL 路径通过 `PG_BIN` / `PSQL_BIN` 指定。

认证与个人中心均访问真实后端，已移除固定用户预览和个人资料内存 mock。登录、注册页不主动查询当前用户；工作台与个人中心通过现有接口恢复会话，失败不会模拟成功。启动后端前须确认目标库已准备并应用现有迁移。短信发送当前仍由后端 mock，固定测试验证码 `095270` 统一定义在 `@tyde/shared` 的 `MOCK_SMS_CODE`；后端通过 `MOCK_CODE` 使用，前端不另行定义，只在发码成功后展示同一值。验证码有效期和校验由后端决定；接入真实短信时须同步移除固定测试码提示。

一键启动本机后端和 Electron，数据库使用 `apps/server/.env` 的配置：

```sh
pnpm dev:local
```

该命令从 `apps/server/.env` 读取数据库配置并覆盖 shell 中的同名旧配置，拒绝 `_test` 库。配置为 `127.0.0.1` 或 `localhost` 的默认 5432 端口时，已监听则复用，否则先启动 `.local/postgres` 中的已有实例；缺少数据目录或启动失败时停止，不自动初始化、清库或执行迁移。远程数据库及其他地址/端口由用户自行启动。随后启动新的本机后端，确认后端身份及数据库就绪后再启动客户端；后端端口已占用时提示先停止原服务，避免复用仍连接旧库的后端。Ctrl+C 只停止本次启动的开发进程，保留 PostgreSQL；Electron 正常退出或第二实例转交后，后端及本次启动的页面服务保留到 Ctrl+C，供现有窗口继续使用。切换配置时先停止旧的启动命令并退出 Electron，再重新执行 `pnpm dev:local`。

也可分别打开终端：

```sh
# 终端 1：独立后端
pnpm dev:server

# 终端 2：Web
pnpm dev:web

# 终端 3：Electron（自动启动或复用 5174 端口的桌面页面服务）
pnpm dev:electron
```

Web 地址：<http://127.0.0.1:3001>。认证入口默认打开“验证码登录”，可切换“密码登录”，不选择角色或账号类型。两种方式分别访问后端短信登录、密码登录接口；登录成功后查询当前用户并进入欢迎页。首次打开密码页即展示“验证码注册”，点击保留手机号、清空密码和验证码、切回验证码页并聚焦输入框，不自动发码。

发码成功后保留后端实际返回的提示，并补充“测试验证码：095270”；提示已含验证码时不重复追加，失败或限流时不显示测试码。验证码校验、有效期和新老账号判断均由后端完成。当前发码响应为提示文字，不另设验证码或成功后的重发间隔字段，前端不猜测成功倒计时。限流时按 HTTP 429 的 `Retry-After` 倒计时。后端返回新账号注册指引时，手机号与一次性凭证仅在内存中传入 `/#/register`，刷新、直访或凭证过期须重新验证手机号。

资料页保留密码、确认密码、姓名、昵称、身份证号和邮箱，不重复填写手机号或验证码，不提供角色或组织注册。页面继续提交兼容字段 `accountType=INDIVIDUAL`，调用现有统一注册接口，不在注册时创建组织；注册成功后回到密码页提示登录，不自动建立会话。已登录用户刷新可通过后端恢复会话；退出请求成功后清除页面会话缓存。网络或服务错误显示实际错误，不回退为本地 mock，不自动发健康检查。

会话查询遇到网络错误或 HTTP 5xx 时，每 3 秒自动重查；后端热重载恢复后自动继续，成功或返回 401 后停止。其他 4xx 与响应格式异常保留手动重试。后台允许自动重查，但实际计时可能被浏览器节流；仅重查当前会话，不自动重放发码、登录、注册等写请求。

Electron 的 `pnpm dev:electron:test` 加载 `apps/electron/config/test.env` 指定测试后端；shell 中已有的 `TYDE_API_BASE_URL` 优先于文件配置。认证、会话、个人资料与组织读取通过平台适配直接 fetch 可信后端。IPC 仅返回经校验的公开 API 源；桌面使用按后端源隔离的持久 Chromium Cookie 会话，刷新令牌只保留在适配器内存。

Web 和 Electron 的当前窗口按 `F12` 可查看真实业务 HTTP；开发与本地打包资源均适用。IPC 不承载业务请求，也不提供任意 URL 请求能力。

普通开发命令不启动主进程 inspector。需要调试主进程 JavaScript 时，运行 `pnpm dev:electron:inspect`，测试后端使用 `pnpm dev:electron:test:inspect`；这两条命令额外启用 `--inspect=9229` 和 `--experimental-network-inspection`，可在 Chrome 的 `chrome://inspect` 连接 `localhost:9229`。窗口 F12 Network 不依赖主进程 inspector。

Electron 开发命令监听 main / preload 的文件变更，修改 main 后会自动重建并重启桌面窗口。开发版和安装包主窗口按 `F12` 切换开发者工具；Mac 顶部按键默认控制音量时使用 `Fn + F12`。macOS 关闭窗口后应用仍可能在后台运行，再次启动会重新打开或恢复现有窗口；完全退出可使用 Cmd+Q。

Web 通过 `API_PROXY_TARGET` 切换后端，shell 优先于 `apps/web/.env.local`；默认代理到 `http://127.0.0.1:3000`。例如运行 `API_PROXY_TARGET=https://test.example.com pnpm dev:web`，其中域名须替换为已配置的测试后端。HTTPS 目标会自动启用自签名 HTTPS，Web 地址改为 `https://localhost:3001`，后端 `WEB_ORIGINS` 须包含该来源。生产预览同样可设置 `API_PROXY_TARGET`，浏览器 Origin 由后端校验；请求失败显示实际错误。

Electron main 的后端地址依次取 `TYDE_API_BASE_URL`、shell 或 `apps/web/.env.local` 中的 `API_PROXY_TARGET`、本地后端。桌面页面独立使用 `http://127.0.0.1:5174`，可与 Web 同时开发；切换后端配置后，发码、登录、注册及会话请求均访问所选后端。

mock 不会发送短信或验证真实号码归属，请用约定的测试号码。默认生产模式禁止 mock，真实短信后续在 `apps/server/src/modules/auth/sms.ts` 接入。

## 个人中心与接口边界

工作台与个人中心共用公共顶栏。开发与生产均调用真实接口；个人资料只提交发生变化的字段，失败保留草稿，成功使用服务端响应更新会话缓存。简介最多 1000 字符，身份证不回填脱敏值、留空保留，已认证不可修改；昵称、姓名与手机号只读。

| 能力     | 当前对接方式与限制                                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本人资料 | GET `/users/me`；POST `/users/me/update` 保存简介和未认证身份证等变化字段                                                                             |
| 头像地址 | 本地选择 JPG/PNG/GIF/BMP/WebP（最大 10 MiB）先预览，保存时调用现有 `/files/upload`，以 objectKey 和一次性凭证关联资料；也支持 HTTPS 地址及清除        |
| 修改密码 | 同一资料接口提交新密码与确认密码，成功撤销全部会话，当前设备也返回密码登录；失败不模拟成功                                                            |
| 组织读取 | 有效主管/管理员查询 GET `/organizations?orgId=...`；普通成员仅展示 `/users/me` 真实组织摘要。失败显示真实错误与只读重试；完整组织管理位于独立组织页面 |

头像预览、更换与清除集中展示，图片链接默认收起。本地头像只在点击保存时上传；失败保留草稿，资料保存失败的手动重试复用已上传凭证，取消/换图不自动提交，上传凭证只放内存。页面不自动重放失败写请求。真实会话角色切换留在工作台或个人中心，侧栏同步当前角色；共用资料草稿和内存上传凭证保留。领航员/策略官共用资料与账户安全，执行专家个人主页按参考图采用左侧大头像和资料、右侧双列项目卡与纵向概览。概览同屏展示所在项目、年度真实考勤热力图、履约信息和本人申请动态；在概览、个人资料、账户安全后追加我的项目、排班考勤、组织与申请顶层页签，直接进入完整业务模块；概览卡片入口同步选中对应页签，通过顶部概览页签返回概览，不再设置单独返回按钮。窄屏页签自动换行，保留键盘切换。年度图复用月考勤接口与缓存，当前年读取一月至上海当前月，历史年读取十二个月，失败月份明确标注。能力评分和报量尚无接口，保留空状态。组织主管隐藏项目区和我的项目页签，成员/管理员和无组织个人专家保留项目区与页签，数据范围由 main 后端过滤。无有效组织的执行专家可从“个人中心 → 排班考勤 → 为自己排班”设置本人班次；有效组织主管/管理员可从“组织管理 → 排班管理”查询成员月历、选择成员批量排班或点击日期编辑每日班次，也可从本人考勤的“管理组织排班”直达。普通成员仅查看本人班次，由组织管理员统一安排。请假/修正、考勤撤回和个人中心退出组织已通过现有接口接入，入口按真实身份及服务端权限显示。“组织与申请”提供正常在组主管的资料编辑入口，复用组织管理表单与真实更新接口，可修改简介和 Logo 图片，保存后同步组织摘要。所有操作沿用公共组件风格；失败保留草稿，409 显式重读，排班和退出按草稿复用幂等键。角色变化通过同源失效通知同步其他标签页，由服务端资料确认角色；读取失败保留资料草稿。接口详情见 [API 文档](docs/API.md)。

后端源码、shared 认证 DTO、Prisma 模型和迁移文件在推送前合并至 `origin/main@daf8431`，客户端保留本分支已提交能力。本次合并只同步源码及第 20—21 项迁移文件，未应用迁移或操作数据库；其他环境的历史验收不代表当前本机或部署库已核对这些迁移。客户端联调不自行修改后端业务或数据库结构；2026-10-23 用户确认的组织 Logo 修改例外，仅补现有接口的图片认领与替换释放，未改数据库结构。

### 提交校验

开发依赖安装后，`prepare` 会配置 Husky；已有依赖、重复安装未触发脚本时，运行 `pnpm prepare` 重新启用。提交前执行：

- `pre-commit`：受限内容守卫检查整个暂存索引的路径与文本，再由 lint-staged 对暂存文件执行 ESLint 和 Prettier 检查。保留未暂存修改，不自动修复或格式化文件。
- `commit-msg`：检查提交信息中的受限内容，不额外要求提交信息格式。
- 全量类型检查、核心测试和双端回归仍按上面的命令按需执行；提交钩子不启动数据库或 Electron。

受限词规则按需保存在仓库根目录的 `commit-policy.json`，已加入 `.gitignore`，仅用于本机校验，不得暂存或提交。JSON 对象中的 `terms` 必须是非空字符串数组；也可用 `TYDE_COMMIT_POLICY_FILE` 指定其他本机文件。默认文件不存在时跳过受限内容检查，其他开发者无需配置即可提交，ESLint / Prettier 检查照常执行。文件存在但无效、规则为空，或显式指定的文件缺失时，钩子会阻止提交。具体名称、标识或其编码不得写入受版本控制的文件。

自动守卫按字面、大小写无关匹配路径、UTF-8 和带 BOM 的 UTF-16 文本。`pnpm-lock.yaml` 的 `packages` 下 `resolution.integrity` 中，算法、长度与 Base64 格式均合法的完整性摘要载荷按机器校验数据处理，避免随机字面碰撞；依赖名、地址、其他字段和注释仍照常检查。二进制只检查路径并提示人工核查。二进制文字与元数据、编码变体、内部依赖及来源仍须遵守 `AGENTS.md` 的完整交付检查，不能仅凭钩子通过判定合规。

## 双端前端开发

- 页面、组件、Hash 路由和业务逻辑只维护在 `apps/web`；Electron 开发时加载同一 Vite 页面，打包时加载同一份 `apps/web/dist`，不另建 renderer 业务工程。
- 认证页采用满页浅青背景与右侧白色悬浮卡片。桌面左侧沿用 main 的英文引导、中文主标题与辅助说明层级，使用当前的潮汐主题文案、协作说明和欢迎语。手机端使用相同背景与白卡，隐藏左侧文案。
- 资料页使用 20px 标题并收紧顶部间距，分为“基础信息”（密码、确认密码）与“个人信息”（姓名、昵称、身份证号、邮箱）两段，保留全部字段与校验；375px 宽手机保持两列，仅宽度不超过 360px 时改为单列，手机卡片左右内边距为 16px。初始、校验错误和提交提示状态以在 1280×720 桌面及典型 375px 宽手机视口内单页完整展示为目标，手机和矮窗仍保留自然滚动，不隐藏溢出内容。
- 布局优先复用现有组件、主题变量与基础样式。页面控制器统一通过 `services/api.ts` 调用能力；认证、会话、个人资料和组织读取均访问现有真实后端；短信 mock 只在后端执行，页面不创建本地验证码挑战或模拟验证成功。
- 登录、注册页不自动查询当前用户；工作台与个人中心启动时查询，开发和生产均恢复真实会话。不自动发起健康检查。开发与生产均请求 `/api/v1/auth/sms/send` 等当前接口；Web 使用同源 Cookie，Electron 页面使用跨源 Cookie 请求可信后端。发码成功显示后端文案，限流倒计时取 `Retry-After`，不会在请求失败时模拟验证码、账号或会话。
- `/#/auth` 提供“验证码登录 / 密码登录”双页签，默认验证码登录，没有独立注册页签或角色选项。密码提交调用真实登录接口；首次进入密码页即提供“验证码注册”，无需先提交。点击注册入口保留手机号、清空密码与验证码并聚焦验证码输入框，不自动发送验证码。
- 短信校验和新老账号判断均由后端完成；只有返回一次性注册凭证的新手机号才进入 `/#/register`。手机号与凭证仅留内存，刷新、直访或离开资料页后须重新验证。资料页保留个人字段，以兼容字段 `accountType=INDIVIDUAL` 调用统一注册，不提供组织创建或材料上传；成功后回到密码登录并保留手机号，不自动登录。已有会话进入欢迎页，退出成功后清除页面缓存。
- 基础组件在 `apps/web/src/components/ui/`，主题变量在 `src/styles/global.css`；通过 `components.json` 配置 shadcn，源码使用 `@/` 别名。表单由 React Hook Form 管理，服务端数据由 React Query 管理。
- 页面通过 `services/api.ts` 和 `@tyde/platform` 调用当前 Fastify API。浏览器继续使用 HttpOnly Cookie，桌面由页面 fetch，使用独立 Chromium Cookie 会话；前端不改用原 tyde-web 的 Java 服务。
- 桌面专有功能通过 `platform.capabilities` 决定是否展示，Web 隐藏不支持的入口；路由与执行入口也需检查能力。当前没有需要页面调用的系统能力，`capabilities` 为空；不提前声明未实现的文件系统、托盘等能力。
- 新业务接口由后端同学实现；联调前先约定 `packages/shared` 中的 DTO/schema、错误和授权方式，前端维护 Web/Electron 适配。当前认证适配已使用 Swagger 与 `packages/shared/src/auth.ts` 中的路径和响应，不再调用旧认证契约。

## 常见问题

- pnpm 11 使用 `pnpm-workspace.yaml` 的 `allowBuilds`，不要改回旧 `onlyBuiltDependencies`。白名单只允许 Electron、Prisma、esbuild 的必需脚本，未使用的 Squirrel 打包脚本被禁用。
- electron-builder 固定为 26.15.3，其依赖链支持 npm 发布的 rebuild / node-gyp；不需要关闭 `blockExoticSubdeps` 或覆盖不兼容的 rebuild 主版本。
- `renderer config is missing` 是 electron-vite 对省略 renderer 配置的提示；本项目只让它构建 main / preload，React 由 Web 工程独立构建。
- 首次配置错误时后端明确退出；数据库不可用时 ready 接口返回 503，不会模拟认证成功。
- 开发端口被占用时先检查服务，不自动变更端口。停止项目数据库：`pnpm db:local:stop`；此命令保留所有数据。
- Windows 只做客户端验收不需要数据库；若要用 Windows 打包，只需源码、Node、pnpm，运行 `pnpm install` 后执行打包命令。
