# Agent 开发与跨端协作

2026-10-20 · 协作说明 v0.2 · W1 工程骨架与 pi-web 前端基础代码已接入

本文供业务前端、Agent 前后端、桌面和业务后端开发共同使用，直接说明工程落点、协作边界与验收要求。内容按当前 tyde 仓库、Agent 架构 v0.10、最小版本计划 v0.2 和核心数据模型草案 v0.1 整理，阅读本文无需访问仓库外的设计目录。

“当前实现”以代码、共享 Schema 和可运行命令为准；下文标为计划、目标或草案的内容仍需开发与验证。当前只冻结进程健康检查契约；任务接口、事件字段、表结构和授权方式尚未冻结，本文不替代已实现的 API 契约。

目标调用关系：

```text
业务页面 apps/web ──→ 平台适配 ──→ 业务后端 apps/server
Agent 页面 apps/agent-web ──→ Agent 服务 apps/agent ──→ MaaS
```

目标中 Pi 仅在 Agent 服务端执行。W1 尚未安装 Pi SDK，也未连接模型或数据库；桌面打包仍只有业务前端，后续装配两份前端资源，数据库和共享模型凭据只在服务端使用。Agent 服务与业务后端分别发布；当前业务后端／Vercel 发布链路尚不承载 Agent 长任务。

## 2 开发职责与公共变更

| 负责方向   | 主要工作                                                 | 需要共同确认的部分                                    |

| Agent 后端 | Agent API、归属校验、任务协调、Pi 适配、工具、存储和日志 | 平台身份委托、业务接口、MaaS 路由与持久化边界         |
| 业务后端   | 平台身份与业务权限、查询、规则、试排、草案及正式提交     | 长任务授权、业务幂等、操作结果查询与可信回执          |

业务前端任务不自行扩展 `apps/server` 的业务接口或业务表；缺失能力先与业务后端负责人确认。Agent 后端任务按授权范围实现 `apps/agent` 的接口、执行状态和数据迁移。人员可以兼任，实际任务范围和负责人需明确。

涉及 `packages/shared`、`packages/platform`、Electron 主进程／preload、根脚本或锁文件时，在变更说明中列出受影响应用、调用方适配和验证结果。`packages/shared/src/agent/` 只放 Agent 跨应用契约，Pi 内部实现、数据库客户端和服务端密钥留在 Agent 服务。

业务页面继续经自己的 `services/api.ts` 使用平台适配；Agent 页面在自身客户端层集中处理远程请求、事件及错误。Agent 工具通过认可的业务 API 访问业务能力，不直接导入业务后端 service／Prisma 实现或操作业务表。

## 4 契约与产品语义

W1 已冻结 `GET /health/live`：返回 `{ "service": "tyde-agent", "status": "ok" }`，匿名、无请求参数，仅表示 HTTP 进程存活。共享路径、DTO 和 Schema 位于 `packages/shared/src/agent/index.ts`；Swagger 由 Agent 服务 `/api/v1/docs/` 提供。页面通过 `/agent-api/health/live` 的同源代理读取并校验返回值，失败显示真实错误，不生成对话或模拟执行。

任务 API、事件和跨端 DTO 后续按最小闭环冻结，再由各端依同一份 Schema 实现。新增 HTTP 接口沿用 [API 文档标准](API.md#swagger-文档标准)，补齐中文说明、错误与幂等语义、真实可校验示例；事件另需说明顺序、重复、断线补齐和终态通知。

| 对象                  | 协作时的含义                                                             |
| --------------------- | ------------------------------------------------------------------------ |
| Conversation 产品会话 | 用户查看历史、发送需求的产品入口；首期仅所属用户可查看和操作             |
| Task 业务任务         | 一项目标及其确认的业务范围，不能等同于每条消息或每次模型调用             |
| Attempt 执行尝试      | 一次准备、恢复核对、执行与结果处理；结束后继续／重试产生新尝试           |
| Command 用户命令      | 发起、补充、继续、重试或停止的一次意图；接收、协调处理和输入消费分别确认 |
| Pi Session／Revision  | 原生执行上下文及其已提交版本，包含分支和资源关联；不是产品聊天文字       |
| Operation 业务操作    | 需要核对业务效果的稳定操作身份，同一操作重试保持原标识、内容及范围       |
| Result 交付结果       | 已可信保存的回答或业务结果引用，流式临时文字和模型自称成功不能替代它     |

数据模型草案的首期产品约定：一个产品会话最多绑定一个 Pi 会话，同时最多一项未完成任务。未完成包括待执行、执行中、待补充、停止中、已停止、中断和失败；当前目标完成前，其他目标另开会话。任务完成后的新问题或草案调整创建新任务，保留原完成事实。这些约定须在接口冻结时确认，草案字段与索引尚不是已实现契约。

同一网络请求重试复用原请求标识和内容；用户新的明确意图使用新标识。继续／重试需关联原任务和明确的尝试，由服务端校验并幂等协调，不能仅凭按钮禁用防止重复执行。停止针对指定尝试，迟到的旧停止请求不能停止后来的新尝试。具体字段名、版本和错误码待共享契约冻结。

## 5 身份、业务上下文与结果回流

tyde 已有登录、用户与组织能力。当前 Web／Electron 页面经平台 HTTP 适配使用 Cookie，Electron preload／IPC 只提供公开运行配置；这不代表独立 Agent 服务已具备平台授权。服务间委托、长任务续期、撤销及退出登录后的处理需共同确定。

- 首期会话为用户私有。组织、部门及可访问的业务数据只决定任务业务范围，不赋予读取他人会话的权限。
- 可信用户来自授权适配，客户端提交的用户／组织标识和页面显示信息不能直接作为凭据。Agent 校验会话及任务归属，业务后端每次调用独立校验原用户、组织范围、规则和数据版本。
- MVP 固定测试身份仅用于显式开启的内部开发／测试模式，并保留服务端归属校验；开放给真实用户前接入认可授权。验证平台登录时设置 `VITE_MOCK_CURRENT_USER=false`，业务页面的预览用户不能作为 Agent 身份。
- 退出登录或切换身份后，旧任务保留原归属，不能静默改用新身份。正常退出应用的取消协调与平台授权失效分别处理。
- 后续接入业务页面上下文时，在输入框旁展示部门、日期和选中对象等引用，允许查看和移除；服务端确认后固定任务范围。切换页面不改变既有任务，未保存编辑须作为显式临时输入处理。
- 候选有效、草案已保存、正式排班已生效分别确认。业务后端返回可信结果引用，业务前端点击查看时重新取数；正式提交由用户确认后交给业务后端校验执行。

## 6 存储、恢复与业务写入边界

业务模型及迁移继续由 `apps/server/prisma` 管理。Agent 仓储计划集中在 `apps/agent/src/storage/`，按 Kysely＋pg 方向验证，迁移放在 `apps/agent/migrations/` 并使用独立命令。可以共用 PostgreSQL 实例，但数据库／schema 和账号权限隔离方案须在正式接库前确定；测试只使用可清理的专用测试库。

完整 Pi 原生状态唯一保存到 PostgreSQL，包含会话头、完整条目、原追加顺序、树关系、活动分支和已提交版本。运行时使用内存会话，不保留 JSONL 恢复分支、本机 SQLite 账本或从聊天表重建上下文的路径。日志用于排障，不能代替恢复状态或交付记录。

同一 Pi 会话只有一个有效写入者。输入消费与原生输入关联提交；原生工具调用和需要的操作意图提交后才发出请求；真实回执先可靠保存，原生工具结果提交后才允许后续模型执行。正常完成时将末尾原生状态、结果、完成事实及待发送通知受控提交，保存失败阻断新的模型／工具调用。普通 SDK 事件订阅不能视为已实现可等待的提交控制，相关适配需验证。

数据库事务不跨模型请求或业务网络调用。恢复先确认旧执行者失效并核对输入和业务事实；心跳超时、桌面断线或原生取消不能证明业务没有生效。已确认目标满足时可以直接交付，不强制再次调用模型。

MVP 只读工具可后置 Operation 表和业务对账接口，仍须完整保存工具调用与结果。接入保存草案等有业务效果的工具前，必须落实稳定操作标识、后端幂等及其保留期限、原请求内容和范围、可信回执与结果查询。结果未知先核对，“暂时查不到”不能直接触发重新写入；停止不能回滚已经成功的业务事务。

## 7 桌面行为与状态展示

目标采用一个主窗口装载独立业务视图与 Agent 视图，Agent 侧栏和完整页沿用同一会话。`BaseWindow＋WebContentsView` 是待验证路线；当前代码仍是 BrowserWindow 单业务页面。HTTPS／JSON 用于命令，首期事件建议 SSE，具体授权与重连协议尚待冻结。

| 动作或状态               | 目标行为                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| 切页、收起、最小化或关窗 | 服务端任务继续，不能因视图隐藏发送取消                                                                 |
| 刷新、断线、休眠后重连   | 查询原会话与任务，补齐展示并恢复订阅，不创建新的执行                                                   |
| 服务端执行中断           | 显示已确认的中断，等待用户继续；新尝试先核对再执行                                                     |
| 停止中                   | 显示尚未确认停止，不提前开放新的继续执行                                                               |
| 已停止／已完成           | 以服务端持久确认的事实为准，不由连接断开或流式结束推断                                                 |
| 正常退出应用             | 停止接收本客户端新任务，仅请求停止其明确关联的任务与尝试；取消受理与实际停止分开，失败或超时显示未确认 |

重连、继续、重试和退出取消都不能误操作其他客户端任务。任务已完成后到达的停止请求不能覆盖完成结果。取消等待时限、未送达处理和事件补齐方式在接口／桌面联调时确定。

Electron 需接入第二份前端的构建资源、开发地址、可信 Agent 服务地址、静态资源路由、来源与 CSP、视图释放及退出协调。沿用 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、`webSecurity: true`，受限 IPC 用于公开配置、原生能力和视图协调，不提供通用 HTTP 或任意 URL 请求能力。
