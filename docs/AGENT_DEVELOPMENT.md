## 4 契约与产品语义

W1 已冻结 `GET /health/live`：返回 `{ "service": "tyde-agent", "status": "ok" }`，匿名、无请求参数，仅表示 HTTP 进程存活。共享路径、DTO 和 Schema 位于 `packages/shared/src/agent/index.ts`；Swagger 由 Agent 服务 `/api/v1/docs/` 提供。该健康接口保留供显式诊断。W3 页面连接身份后通过 `/agent-api/api/agent/v1/*` 同源代理访问产品接口，失败显示真实错误，不回退为模拟执行。

21 号命令、22 号查询与 SSE 的 `1.1.0-design` 原始 OpenAPI 快照、来源 SHA256 以及 99 个去重公开 Schema 的生成代码随仓库保存，见 [共享契约说明](../packages/shared/src/agent/contracts/README.md)。两端通过 `validateAgentContract(name, value)` 校验，不直接以 TypeBox `Value.Check` 替代这套校验器。新增 HTTP 接口沿用 [API 文档标准](API.md#swagger-文档标准)，补齐中文说明、错误与幂等语义、真实可校验示例；事件另需说明顺序、重复、断线补齐和终态通知。

2026-10-22 W2 开始时，两份 21／22 号 JSON 与当时仓库 `1.0.0-design` 快照逐字节一致，未更新生成代码。W3 重新核对后，同步当前未带历史后缀的 `1.1.0-design` 源快照和来源摘要：路径及 21 请求 Schema 未变，新增预算／停止竞争语义；22 新增 `AttemptBudgetView`、`AttemptView.budget` 及相关错误、示例。公开 `schema_version` 仍为 1，须协同升级严格校验器。24 号模型流始终是服务端独立协议，不进入 22 号产品 SSE 解析器。

| 对象                  | 协作时的含义                                                             |
| --------------------- | ------------------------------------------------------------------------ |
| Conversation 产品会话 | 用户查看历史、发送需求的产品入口；首期仅所属用户可查看和操作             |
| Task 业务任务         | 一项目标及其确认的业务范围，不能等同于每条消息或每次模型调用             |
| Attempt 执行尝试      | 一次准备、恢复核对、执行与结果处理；结束后继续／重试产生新尝试           |
| Command 用户命令      | 发起、补充、继续、重试或停止的一次意图；接收、协调处理和输入消费分别确认 |
| Pi Session／Revision  | 原生执行上下文及其已提交版本，包含分支和资源关联；不是产品聊天文字       |
| Operation 业务操作    | 需要核对业务效果的稳定操作身份，同一操作重试保持原标识、内容及范围       |
| Result 交付结果       | 已可信保存的回答或业务结果引用，流式临时文字和模型自称成功不能替代它     |

数据设计与接口基线的首期产品约定：一个产品会话最多绑定一个 Pi 会话，同时最多一项未完成任务。未完成包括待执行、执行中、待补充、停止中、已停止、中断和失败；当前目标完成前，其他目标另开会话。任务完成后的新问题或草案调整创建新任务，保留原完成事实。W3 已在进程内落实上述互斥与状态裁决，数据库表、索引及持久提交仍待 W5。

同一网络请求重试复用原请求标识和内容；用户新的明确意图使用新标识。继续／重试需关联原任务和明确的尝试，由服务端校验并幂等协调，不能仅凭按钮禁用防止重复执行。停止针对指定尝试，迟到的旧停止请求不能停止后来的新尝试。五类命令、原目标和版本字段以共享契约为准。W1 提供格式与摘要基础，W3 已实现进程内请求去重、同 key 意图冲突和指定 Attempt 停止。`provide_input`、`continue_task`、`retry_task` 尚不支持，页面不展示可用入口；持久去重和尝试恢复仍待 W5，不能用 SDK 方法冒充完整产品语义。

### 4.1 W1 可复用的契约基础

- 命令与查询使用 `/api/agent/v1`；五类命令为 start／provide input／continue／retry／stop，命令确认与当前任务／输入状态分别读取。版本与可靠事件序号使用 bigint 十进制字符串，不能转换成 JavaScript Number。
- `apps/agent/src/commands/prepare-command.ts` 校验并固定 v1 原语义：UUID 小写、缺失 context 补 `{}`，保留正文、业务 ID 和数组次序。`api_major_version=1`、路径会话及命令字段参与 JCS 摘要，request_key 和 client_instance_id 不参与；使用固定 canonicalize 5.1.0 与 SHA256。此函数接收已解析对象；W3 的 `api/strict-json.ts` 与路由同时检查原始请求的大小、媒体类型、重复 JSON 键及共享 Schema。
- `apps/agent-web/src/agent-events/` 提供分块 UTF-8／多行 SSE 解析及可靠游标基础：product 完整校验、按序成功应用后才推进；control／delta 不推进，也不能继承上一帧 id。断线仅恢复展示，不能借重连启动执行。
- 事件样例仅用于测试：覆盖 7 类可靠产品事件、控制帧和临时文字。服务与页面不使用这些样例模拟成功；实际命令／查询／事件已由 W3 路由和原生执行驱动。
- `pnpm generate:agent-contracts` 从仓库内固定快照生成；`pnpm check:agent-contracts` 验证未漂移。设计修订时先比较差异并更新快照／来源，再生成并运行 `pnpm test:agent`，不直接覆盖业务实现或手改生成文件。

21／22 的结构校验不是数据库关联和跨对象事实验证。W3 已实现 owner 与任务／尝试关联、start／stop 状态裁决、进程内原子投影／水位及事件裁剪边界；可复用 A2、数据库事务、可靠 outbox、持久事件、以及 23 号委托与业务回执仍须在后续工作包实现和验证。

### 4.2 W2 模型执行边界

W2 保留无界面验收，主入口读取服务端 URL／Key；用户已提供 Flash 的两轮召回、流式与本地停止通过日志。Pro 目前仅配置检查，可选平台尚未真实联调。W3 产品 API 复用主入口的服务端配置，具体真实浏览器结果见 [验收记录](AGENT_W3_VALIDATION.md)。

`apps/agent/src/pi/` 封装 `pi-coding-agent`、`pi-agent-core`、`pi-ai` 1.3.0，沿用原生消息、上下文和工具循环；设计核对的源码提交为 `71023aec1546d6d677a65669c5665c0927ce0dd0`。会话、设置、认证及资源来源显式使用内存装配，不继承个人目录或 pi-web 的文件状态。默认不构造内置终端／文件工具，不发现本机 Skills、Extensions、Packages 或提示词；自动故障重试、压缩、摘要和预热均关闭。只放行显式白名单且参数校验通过的工具，首期每轮至多一个，不接真实业务写入。

`src/maas/` 为 Pi `openai-completions` 提供显式配置与受控网络层。主入口的 `direct-model` profile 默认官方 DeepSeek `deepseek-flash`，显式关闭思考；其他 URL 必须指定模型 ID，响应不得隐藏切换模型。它不需要或伪造平台原主体、路由或关联头；后续普通 OpenAI 兼容平台代理也可沿用 URL／Key。`chat-sse-v1` profile 则单独固定平台 `/internal/agent-maas/v1`，校验其服务鉴权、可信原主体、路由和响应关联。两条路径显式选择，失败不互相回退。

完整合法 finish 与 `[DONE]`、没有先前错误及相应 profile 的全部校验共同决定模型轮次成功；残缺流、length／content_filter、未知 finish、多工具或异常用量不能当正常完成，完整参数未校验前不放行工具。主无界面入口当前只验文字多轮，没有装配业务工具。模型流独立于 22 号产品事件；W3 的产品 API／SSE 由独立协调器产生，不能转发供应商片段冒充可靠事件。

停止先撤销执行资格并中止读取，等待本地执行收敛；迟到片段不恢复执行，停止后不启动下一轮模型／工具。授权解析与执行屏障等待也可取消并受准备预算限制。停止／失败前已接受文字保留为原生 aborted／error 事实，不携带可执行工具，也不充当成功交付。独立建连、响应头、首个有效进展、进展空闲和总预算默认分别为 3、15、60、45、180 秒。受控 Undici HTTP 请求不安装重试或重定向拦截器，逐请求释放连接资源。用量缺失保留 null，费用保持未知，不使用 Pi 默认 0 或静态估算冒充实际消费。平台与供应商取消传播、计费和逐路由能力仍需真实验收。

适配边界保留原生快照和可等待执行关口，供 W5 接入；这不表示已经实现 PostgreSQL 保存屏障或可靠结果。普通 SDK 公开订阅仍只用于临时进度，不能当成持久化事务。内存结果仅表示本进程内执行结局，不承诺重启恢复、持久输入消费、可靠业务写入或 21／22 号持久任务完成。

### 4.3 W3 进程内产品闭环与预算

`api/routes.ts` 提供会话 POST／GET、概况、一致 snapshot、消息历史、任务／结果、命令 POST、按 request_key 的只读核实和产品 SSE。空会话 POST 非幂等，不自动重发；命令响应丢失先只读核实，仍有执行意图时仅允许保留原 key、正文、context 和目标原样重发，查询未命中不证明在途命令没有执行。`runtime/memory-runtime.ts` 在同步协调区内更新投影和连续事件水位，冻结公开载荷后保存；不能以发送时的当前对象冒充历史事件。并发同 key 不重复执行，同 key 不同原意图拒绝；同一 Pi Session 至多有一个有效执行者。

前端 `services/agent-client.ts` 集中校验 HTTP／SSE；`chat-controller.ts` 隔离读取代次与当前订阅，先完整安装 snapshot、覆盖缓存和 H，再从 H 之后补读。product 完整校验并成功连续应用后才推进游标；control／delta／心跳不推进。消息按自身 row_version、结果按不可变身份收敛，临时文字按 message／attempt／output_stream_id 及连续索引拼接。缺少起始片段、缺号或重连中途加入时丢弃临时段，等待可靠正文；可靠事件缺口和换流要求重取快照，不静默跳号。旧 HTTP 回包和旧订阅回调不覆盖当前会话。fetch 逐帧等待应用，服务端写循环与客户端解析／投影均有容量边界；暂时断线有限退避后允许手动重新连接。刷新、切换、关闭页面及断开 SSE 都不创建执行，也不等于停止成功。

会话默认标题在首条用户输入受理时取正文预览，折叠空白并截取前 80 个 Unicode 码点；自定义标题保留，不产生额外模型请求。消息右下角显示服务端时间，跨日带日期。尝试统计展示已用模型请求数、工具执行数及按服务端起止时间计算的耗时，运行时更新、终态固定，刷新和重连不重新计时；不向用户展示总额度，服务端预算保护保持不变。Agent 浅色主题对齐业务前端青蓝品牌，深色配色保留可读性。继续／重试仍不开放，本次展示调整不改变产品命令范围。

`execution/attempt-budget.ts` 的新 Attempt 预算默认为 600000ms、12 次模型请求授权、10 次工具执行授权，策略版本 1。queued 时 deadline 为 null，开始后固定；按 Attempt 同步预占并累计，重复授权不重复派发，已授权失败不退计数。恰好使用 N 次仍可完成，尝试第 N+1 次才拒绝且不增计数；期限和计数超限锁存唯一首因，立即撤销执行资格并取消模型／工具。预算超限先于停止时，不能伪造用户停止；用户停止先行则保留停止结局。当前 budget 非空并反映真实授权，历史未追踪投影仍允许缺失或 null，不把未知计数填零。虚拟时钟验证期限、授权边界和停止／完成竞争。

Attempt 累计预算与单次模型请求超时、实际 token 用量和费用独立；SDK 默认 0 不能当真实用量。W3 的同步放行、deadline 与取消只对本进程有效，正式持久预占、提交不明核实、持久 deadline、恢复保护和完整 26 号设计验收属于 W5；不能以本轮边界测试宣称真实 10 分钟或全部预算调优已验收。

## 5 身份、业务上下文与结果回流

W4 的 `pi/resources.ts` 从宿主显式提供的固定内容校验版本和摘要，将 Skill 正文预加载到真实 system prompt；原生自动发现与文件／终端工具仍关闭。默认服务没有演示依赖。`PiNativeState.configuration` 保存不含凭据的执行配置、声明和资源身份；`saveNativeState` 与 `beforeDispatch` 为 W5 留出可等待门禁，未实现数据库事务。只读工具产生独立 `ToolExecutionSummary`／`tool.updated`，进入快照、历史及详情，不产生业务 Operation；新事件和严格校验需两端配套升级。详细语义、验证及 W5 接口见 [W4 验收](AGENT_W4_VALIDATION.md)。

tyde 已有登录、用户与组织能力。当前 Web／Electron 页面经平台 HTTP 适配使用 Cookie，Electron preload／IPC 只提供公开运行配置；这不代表独立 Agent 服务已具备平台授权。服务间委托、长任务续期、撤销及退出登录后的处理需共同确定。

- 首期会话为用户私有。组织、部门及可访问的业务数据只决定任务业务范围，不赋予读取他人会话的权限。
- 可信用户来自授权适配，客户端提交的用户／组织标识和页面显示信息不能直接作为凭据。Agent 校验会话及任务归属，业务后端每次调用独立校验原用户、组织范围、规则和数据版本。
- W1 固定测试身份通过 `AGENT_AUTH_MODE=development` 显式启用，仅允许 development／test 环境且服务监听 127.0.0.1 或 ::1；用户与 Bearer 凭证由服务端配置，无默认凭证，默认 disabled 时不授予资源访问。W3 资源接口通过 `app.agentAccess` 和 `requireOwnedConversation` 校验身份及私有归属；开放给真实用户前接入认可授权。验证平台登录时设置 `VITE_MOCK_CURRENT_USER=false`，业务页面的预览用户不能作为 Agent 身份。
- 退出登录或切换身份后，旧任务保留原归属，不能静默改用新身份。正常退出应用的取消协调与平台授权失效分别处理。
- 后续接入业务页面上下文时，在输入框旁展示部门、日期和选中对象等引用，允许查看和移除；服务端确认后固定任务范围。切换页面不改变既有任务，未保存编辑须作为显式临时输入处理。
- 候选有效、草案已保存、正式排班已生效分别确认。业务后端返回可信结果引用，业务前端点击查看时重新取数；正式提交由用户确认后交给业务后端校验执行。

## 6 存储、恢复与业务写入边界

业务模型及迁移继续由 `apps/server/prisma` 管理。Agent 仓储计划集中在 `apps/agent/src/storage/`，按 Kysely＋pg 方向验证，迁移放在 `apps/agent/migrations/` 并使用独立命令。可以共用 PostgreSQL 实例，但数据库／schema 和账号权限隔离方案须在正式接库前确定；测试只使用可清理的专用测试库。

目标中完整 Pi 原生状态唯一保存到 PostgreSQL，包含会话头、完整条目、原追加顺序、树关系、活动分支和已提交版本，仓储在 W5 实现。W2／W3 运行时使用内存会话；W3 的会话、命令裁决、产品投影和冻结事件日志只在同一服务进程存活期间有效，不保留 JSONL 恢复分支、本机 SQLite 账本或从聊天表重建上下文的路径。日志用于排障，不能代替恢复状态或交付记录。

同一 Pi 会话只有一个有效写入者。输入消费与原生输入关联提交；原生工具调用和需要的操作意图提交后才发出请求；真实回执先可靠保存，原生工具结果提交后才允许后续模型执行。正常完成时将末尾原生状态、结果、完成事实及待发送通知受控提交，保存失败阻断新的模型／工具调用。普通 SDK 事件订阅不能视为已实现可等待的提交控制，相关适配需验证。

数据库事务不跨模型请求或业务网络调用。恢复先确认旧执行者失效并核对输入和业务事实；心跳超时、桌面断线或原生取消不能证明业务没有生效。已确认目标满足时可以直接交付，不强制再次调用模型。

只读演示工具不产生业务操作记录，仍须完整保存工具调用与结果；W1／W2／W3 不建表，也不据此删减第 20 号设计的完整 18 表初始基线。具体迁移及拆分须在 W5 明确。接入保存草案等有业务效果的工具前，必须落实稳定操作标识、后端幂等及其保留期限、原请求内容和范围、可信回执与结果查询。结果未知先核对，“暂时查不到”不能直接触发重新写入；停止不能回滚已经成功的业务事务。

## 7 桌面行为与状态展示

目标采用一个主窗口装载独立业务视图与 Agent 视图，Agent 侧栏和完整页沿用同一会话。`BaseWindow＋WebContentsView` 是待验证路线；当前代码仍是 BrowserWindow 单业务页面。HTTPS／JSON 用于命令，首期事件按 22 号契约使用带 Authorization 的 fetch SSE，浏览器的实际连接／重连已由 W3 接入；正式授权和桌面装配仍待后续阶段。

| 动作或状态               | 目标行为                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| 切页、收起、最小化或关窗 | 服务端任务继续，不能因视图隐藏发送取消                                                                 |
| 刷新、断线、休眠后重连   | 查询原会话与任务，补齐展示并恢复订阅，不创建新的执行                                                   |
| 服务端执行中断           | 显示已确认的中断，等待用户继续；新尝试先核对再执行                                                     |
| 停止中                   | 显示尚未确认停止，不提前开放新的继续执行                                                               |
| 已停止／已完成           | W3 以服务端进程内确认的投影为准，正式阶段要求持久确认；不由连接断开或流式结束推断                      |
| 正常退出应用             | 停止接收本客户端新任务，仅请求停止其明确关联的任务与尝试；取消受理与实际停止分开，失败或超时显示未确认 |

重连、继续、重试和退出取消都不能误操作其他客户端任务。任务已完成后到达的停止请求不能覆盖完成结果。取消等待时限、未送达处理和事件补齐方式在接口／桌面联调时确定。

Electron 需接入第二份前端的构建资源、开发地址、可信 Agent 服务地址、静态资源路由、来源与 CSP、视图释放及退出协调。沿用 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、`webSecurity: true`，受限 IPC 用于公开配置、原生能力和视图协调，不提供通用 HTTP 或任意 URL 请求能力。
