# 统一账号、三角色与组织创建

2026-10-22产品变更，覆盖此前固定EXPERT、个人/组织注册和独立管理授权规则。仅改后端、必要共享契约和文档；未改Web、Electron及平台适配。逐接口进度与验证以[插队任务](../../backend-migration/priority-unified-accounts/todoTask.md)为准。

## 账号与会话

- 统一手机号注册，不选择个人或组织身份，不在注册时建组织。注册成功账号ACTIVE，不自动登录。原验证码、一次性注册凭证、风控及改密撤销全部会话规则保留。
- 每个有效账号自动具备NAVIGATOR（领航员）、PM（策略官）、EXPERT（执行专家）；无需审批或独立授予。不含OPS。`User.role`、`ManagementGrant`及其历史审计保留结构，但不再作为三角色业务授权来源；旧授权维护命令返回409，不会假装授予或撤销。
- 登录可省略role，默认EXPERT；可提交客户端记住的NAVIGATOR/PM/EXPERT。OPS返回403。服务端只接受经密码/短信验证的会话角色，不接受请求头伪造角色。
- `POST /auth/switch-role`（API-121）提交`{"role":"PM"}`；返回`{"code":200,"message":"操作成功","data":{"selectedRole":"PM","roles":["NAVIGATOR","PM","EXPERT"]}}`。只变更当前会话，不更换令牌，不影响其他会话；刷新令牌保留角色。角色切换、组织创建与认证改密共用本人认证锁。
- 同一会话的浏览器页签共享角色；不同会话分别切换。服务端不根据全账号最后角色影响其他设备。跨退出/重新登录记住角色由客户端本机存储并在登录时提交role；本轮未实现前端保存或切换UI。
- 注册、本人资料及资料更新的`roles`返回三角色；`role`为当前会话角色，无会话的注册响应默认EXPERT；`selectedRole`注册为null，查询/更新为实际会话角色。`hasExpertManagementRole`仅当前EXPERT且有有效OWNER关系或已接单组织现任项目负责人关系时为true；负责人须仍在对应组织，任何负责人历史阻止旧单值回退，删除项目不授予管理职责。065/066及该分支已由07接入待验收，仍不作为鉴权凭据。
- `accountType`保留兼容字段：注册可省略，仅接受INDIVIDUAL；输出固定INDIVIDUAL。`roles`注册/资料更新输入仅兼容忽略，不减少三角色、不授予OPS。注册不再接受organization/orgPosition；组织身份通过UserOrgRel表达。
- `GET /users/me`及资料更新新增`organizations`数组，返回全部可参与关系的组织摘要（id/name/position/joinStatus/status/verifyStatus），无组织为空数组；按组织ID排序。原单数organization保留OWNER优先、最早加入的展示摘要，不是当前操作组织，不能用其自动授权别的组织。

## 创建组织

API-124：`POST /api/v1/organizations`，有效登录且当前EXPERT。Cookie/来源和Bearer隔离规则沿用现有认证接口，禁止借前端隐藏入口代替后端校验。

```json
{
  "name": "示例标注团队",
  "unifiedCreditCode": "EXAMPLE_CREDIT_CODE",
  "description": "提供数据标注服务。",
  "logoUrl": "https://example.com/logo.png",
  "expertiseTags": ["图像标注"]
}
```

资料和校验沿原组织注册：name必填、trim后非空且唯一；信用代码、营业执照、简介、Logo、标签均选填。营业执照仍使用`businessLicense:{objectKey,uploadToken}`，先通过`POST /files/upload`上传BUSINESS_LICENSE，不能提交敏感公开URL。营业执照凭证默认24小时有效，可匿名预上传；持有正确凭证才能一次性认领。Logo本地图片使用登录后的`ORG_LOGO`上传，在创建时提交`logoUrl=objectKey`和`logoUploadToken`；校验本人上传及凭证，认领与组织/主管关系创建同事务，返回可展示URL。Logo也兼容外部HTTPS地址。无新认证审核要求。

组织写为ACTIVE、verifyStatus=APPROVED（创建即生效，不代表人工认证）；创建人的关系固定ACTIVE/OWNER，不能由客户端指定管理员或创建人。组织、关系及营业执照认领同事务，失败全部回滚；已有账号和注册凭证不属于该事务。成功返回组织完整资料，结构与GET /organizations的data相同，含id/name/position/status/verifyStatus等中文Swagger字段。

允许一人创建多个组织，也允许在其他组织任职期间创建组织。成员导入只拒绝当前组织的有效重复成员，不再因存在其他组织关系拒绝；其他组织的身份、管理员名额及项目数据不能转用到本组织。每个组织原管理员上限、主管转让、退出/离职流程及成员状态仍分别校验。组织创建不自动接单、不授予项目范围，不修改User.organizationId/orgPosition兼容缓存。

重名/重复信用代码返回409；同名并发创建仅一方成功。重复提交不自动重放成功，沿唯一约束返回409。营业执照错误凭证403、过期/重复认领409、无登记或内容不符400、存储不可用503，失败不得留下孤立组织或成员关系。
