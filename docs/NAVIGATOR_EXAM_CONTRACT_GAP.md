# 领航员准入考试：现有能力及目录待确认项

本文记录本轮前端接入决定和仍需后端确认的目录问题，不新增后端契约。人工阅卷、历史绑定卷读取和附件接口均已存在；本轮复用这些接口，不新增后端响应字段、数据库结构或迁移。

## 历史与已关闭考试已有人工阅卷能力

现有 `POST /entrance-exams/grading/detail` 按考生绑定的历史版本和原卷返回实际轮次、执行记录、题目与答案。现有 `POST /entrance-exams/grading/manual` 允许历史版本和 CLOSED 考试，不要求所选轮次仍属于当前配置版本。

人工提交在事务内独立校验：

- 当前会话属于命令允许的业务角色，本人在实际绑定轮次的 `reviewersJson` 中；项目创建人、需求方、主策略官或项目阅读资格均不能代替本轮阅卷安排。
- 轮次为 MANUAL，实际执行记录属于该应试及绑定版本，状态为 PENDING/PROCESSING；考生已交卷并绑定原卷，前序轮次全部完成。
- 提交完整判定实际试卷全部题目，保持题目、答案和逐题记录来源一致；已完成记录不可修改，重复提交返回 409。

源码依据：`apps/server/src/modules/entrance-exams/exam-grading-query.ts` 的 `queryExamGradingDetail`；`exam-grading-command.service.ts` 的 `submit`；`exam-grading-command.schema.ts` 的人工提交说明。

## 本轮前端决定：读取状态后提交，资格由现有 POST 核验

成功读取阅卷详情后，前端按实际 MANUAL 轮次、PENDING/PROCESSING 状态、存在执行记录和前序完成情况提供人工判定与提交入口。入口表达用户可以发起本次提交请求，不表示前端已证明本人拥有该轮最终写权限；POST 的真实鉴权决定能否保存，403 明确反馈并保留原稿。

当前配置仅返回 ACTIVE 考试的当前版本，不能作为历史人工提交的必备条件。本轮移除“当前配置可读、轮次 ID 与当前配置相同、当前 reviewer 快照含本人”等额外前端门槛，不因 CLOSED、历史版本或配置读取失败禁止现有后端允许的人工请求。也不以新增 `canSubmitManual` 等响应字段作为接入前提。

仍须保留以下已有保护：

- 使用真实 NAVIGATOR 会话，读取和异步结果前后核对当前账号、角色；不以创建人或 `needAssistGrading` 推定写权限，不开放 PM 配置写入或 AUTO 重试、补偿。
- 提交前重新读取，确认同一考试、应试、全局 `gradingRoundId`、`gradingRecordId` 和完整题目集合；不以当前配置覆盖考生实际绑定版本。
- 完整逐题判定，意见和总结长度校验，发送前按 16 KiB UTF-8 JSON 上限检查。
- 原稿和待核实命令按账号、实际执行记录保留，跨角色互斥；403 等明确拒绝与未知结果区分。网络、5xx、会话变化或异常响应不自动重发；无幂等键的人工提交不能通过普通读取结果猜测成功后再次发送。
- 成功先记录 success，再读取最新轮次和完整 NAV 待办续接；后续读取失败只重试读取，不能重发已成功命令。

阅读范围与提交资格仍由两个已有后端入口分别控制。前端取消额外资格推断，不扩大任何后端授权，也不声明“可读即有权保存”。

## 非创建人的阅卷目录来源缺口

现有 `GET /projects/list` 的 NAVIGATOR 项目范围按本人 `uid = project.createdBy` 查询。因此，被配置为其他人创建项目的阅卷人，即使现有考试 Viewer 和人工提交命令允许，也无法通过该目录发现对应项目。

`needAssistGrading` 只检查 ACTIVE 考试当前版本的人工池；它既不是某次执行记录的提交资格，也会遗漏历史版本和已关闭考试。`branchNodeCode=ENTRANCE_EXAM_GRADING` 来自实际待处理记录，但支线竞争可能被更高优先任务遮挡。两者均不能用来扩大人工提交权限。

`GET /projects/workbench/statistics?mode=TASK` 已识别非创建人的历史人工阅卷来源，但只返回待办数、完成数和涉及项目数，不返回可导航的项目或阅卷记录列表。看板项目列表及基础详情的 NAV 范围也仍限创建人，不能替代此目录。

建议后端确认：在原目录范围内合并本人实际待阅卷来源，依据已交卷、MANUAL、PENDING/PROCESSING 的真实记录及其历史轮次阅卷池确定项目，按项目去重并沿用现有卡片仲裁。不要把全部项目、全部创建历史或仅当前版本的阅卷池当作待办目录，也不要通过客户端猜测项目 ID 补齐来源。具体接口范围及兼容方案尚未实施。

目录合并还不足以接通页面：现有 `ProjectQueryService.detail` 仅允许创建人 NAVIGATOR 读取通用项目详情，当前 `ProjectDetailPage` 也在该详情成功后才装配考试模块。非创建人的合法阅卷卡即使出现在目录中，仍会在此处遇到 403。接续方案须同时确认受限的项目上下文读取，或由前端使用目录提供的真实项目来源进入独立阅卷入口，仅读取既有考试 Viewer 数据。不能直接扩大全部项目详情权限，也不能把只改目录宣称为完整接通。

## 变更边界

仓库 `AGENTS.md`“业务前端任务”约定要求按既有 API 和 DTO/schema 对接，语义缺口先列清单与后端确认；业务后端 DTO/schema、路由和 service 由后端负责人维护。本轮人工阅卷直接复用已实现的读取与提交鉴权，不以修改后端 DTO 为前提。非创建人的目录和项目上下文接续仍是实际缺口，以上目录合并方案尚未实施，也不能宣称已完整接通这类待办。
